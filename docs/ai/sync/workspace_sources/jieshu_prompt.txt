你现在要为“下一次新的 agent 会话”生成一个完整的工程交接文档。

目标：

让新的会话无需阅读旧长上下文
能快速、安全、准确地继续开发
减少 hallucination
避免重复调查和错误修改

请输出一个结构化 markdown 文档。

要求：

1. 项目当前目标

说明当前正在做什么，以及最终目标是什么。

2. 当前完成状态

列出已经完成的工作。

3. 最近的重要修改

包括：

修改了哪些文件
做了什么改动
为什么这样改
4. 当前架构/设计决策

说明重要设计原则、约束、tradeoff。

5. 未完成事项（TODO）

按优先级列出。

6. 已知问题 / 风险

包括：

潜在 bug
技术债
不稳定区域
需要特别小心的地方
7. 下一步推荐行动

明确告诉下一会话：
“第一步应该做什么”。

8. 不要做什么

列出已经验证失败的方案、不要重复的错误方向。

9. 关键上下文速记

包括：

重要命令
测试方式
环境注意事项
repo structure
API 特殊行为
等。

要求：

不要写无意义总结
不要重复废话
尽量具体
假设下一会话完全没有旧上下文
输出必须可直接保存为 SESSION_SUMMARY.md, 控制在 1000 行以内。
