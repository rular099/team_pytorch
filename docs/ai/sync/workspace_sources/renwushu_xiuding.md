# Codex 补充任务：FE01/FE02 并行开发与项目记忆隔离

这是对之前 `PROJECT_MEMORY_BOOTSTRAP` 任务书的修订。若原任务已部分执行，请在现有成果基础上调整，不要无条件重建文件。

## 关键事实

TEAM_PYTORCH 中 FE01 和 FE02 是两条并行开展、需要独立管理的科研工作线。

两者共享部分基础代码和研究背景，但实验目标、方法、分支、结果和后续计划均需要独立维护。

FE01 与 FE02 可能同时运行两个 Codex 实例，并同时在超算开展实验。

## 必须修改的设计

### 1. 独立记忆

不再使用单一 `FE_SERIES.md` 作为 FE01/FE02 的共同进度文件。

分别建立：

- `docs/ai/memory/tracks/FE01/`
- `docs/ai/memory/tracks/FE02/`

每条实验线分别保存 STATUS、DECISIONS、EXPERIMENT_INDEX、CHAT_HANDOFF。

其他实验线遵循同样原则。

### 2. 单独写入

FE01 Codex 只更新 FE01 专属状态文件。

FE02 Codex 只更新 FE02 专属状态文件。

全局记忆和汇总状态文件只能由协调者更新。

除非用户明确授权，不允许两个实例同时修改全局状态文件。

### 3. Git 隔离

支持两个 Codex 使用独立 Git Worktree 和独立分支并行工作。

不得要求用户停止 FE01 才能启动 FE02，反之亦然。

确认两条实验线各自的实际活跃分支和 commit，不根据分支名称推测最新进度。

不要重写已有 Git 历史，也不要强制合并两条实验线。

### 4. 状态汇总

全局 CURRENT_STATUS 必须分别显示 FE01 和 FE02 的状态。

每条记录包括：

- track_id
- branch
- commit_sha
- last_verified_at
- current_state
- verified_results
- pending_tasks
- evidence_paths

统一协调者应能够从两个远端分支独立读取状态，并生成全局摘要。

不得把未同步视为未完成，也不得用一条分支的状态覆盖另一条分支。

### 5. 实验产物隔离

检查并规范 FE01/FE02 的：

- checkpoint 输出目录
- HPC 作业和日志目录
- 评估结果目录
- 临时文件
- 缓存写入行为
- 实验 ID

不得在同一路径发生并发覆盖。

### 6. 并行修改共享代码

允许两个实验分支修改相同的基础代码，但必须保持独立提交。

在合并代码前：

- 检查不同修改的兼容性；
- 运行必要的回归测试；
- 不得自动选择一方覆盖另一方；
- 对共享模型架构变更执行单独审阅。

### 7. 验收测试

模拟两个 Codex 并行工作：

A 更新 FE01 状态，B 更新 FE02 状态。

验证两条记录都能保留，并且统一协调者能正确生成同时包含 FE01、FE02 的项目汇总。

再模拟两条实验线更新不同分支但涉及同一代码文件的情形，确认不会直接互相覆盖，并能识别后续合并风险。

## 实施顺序

先由一个 Codex 实例建立、测试并提交全局记忆体系。

经过审核后，将必要的公共文档变更安全引入 FE01、FE02 各自的工作分支。

完成初始化后，再允许两个 Codex 实例长期独立维护各自的实验线。

最终提交一份并行开发与记忆管理说明，包含初始化命令、日常操作规范和故障恢复方法。

本任务不得修改科研模型逻辑，不得自动提交超算作业，不得删除历史实验结果。
